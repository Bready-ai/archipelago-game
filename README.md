# ПУСТОШЬ · Первая схватка

Небольшая 3D-схватка на Three.js и Vite. Модели, эффекты и звуки создаются в коде.

**Игра:** https://bready-ai.github.io/archipelago-game/

## Публикация

Один раз в репозитории: **Settings → Pages → Build and deployment → Source → GitHub Actions**. После слияния изменений в `main` workflow **Deploy game to GitHub Pages** автоматически собирает игру и публикует `dist`. Ручной запуск: **Actions → Deploy game to GitHub Pages → Run workflow → main**.

Состояние: **Actions → последний запуск → build / deploy**. Зелёный `deploy` означает успешную публикацию. При запросе подтверждения окружения нажмите **Review deployments → github-pages → Approve and deploy**. Обновите страницу игры на телефоне после завершения деплоя.

Используются только официальные GitHub Actions и встроенный `GITHUB_TOKEN`/OIDC. Секреты и платный хостинг не нужны. `base` берётся из настроек Pages; локальная сборка по умолчанию использует `/archipelago-game/`.

## Управление

**Android / Chrome:** удобнее горизонтально. Джойстик слева — движение, справа — удар (можно удерживать для серии) и уклонение. Персонаж плавно поворачивается к ближайшему живому врагу; направление атак корректируется умеренно. Движение, удар и уклонение работают с отдельными касаниями. После смены ориентации бой ставится на паузу.

**Компьютер:** WASD — движение относительно экрана, мышь — направление, ЛКМ — один удар, Space — уклонение, Esc — пауза, R — перезапуск.

Рендер ограничивает pixel ratio и число пикселей; на телефонах уменьшены тени и эффекты. При устойчивом падении FPS разрешение снижается, а на самых слабых устройствах остаются контактные тени.

## Локальная проверка

Node.js 22.12+:

```sh
npm ci
npm test
npm run build
npm run check:dist
npm run preview
```

Для разработки: `npm run dev`. Для другого пути: `VITE_BASE_PATH=/my-repo/ npm run build` (для проверки путей передайте ту же переменную в `npm run check:dist`).

Лично проверьте на телефоне: ходьбу с одновременным удержанием удара, уклонение третьим касанием, отсутствие залипания после паузы/сворачивания, читаемость дальности и восстановление после атаки. Эмуляция не заменяет проверку физического телефона.

## Диагностика запуска

При сбое экран показывает исходную ошибку, этап запуска, сборку, статус WebGL 2 и попытки создания контекста. Кнопка **Копировать диагностику** копирует отчёт; при недоступности Clipboard API используется обычное копирование из текстового поля. Автоматической отправки данных нет. Идентификатор работающей сборки также виден на паузе.

Проверки production-запуска выполняются в Actions перед публикацией и для PR. Локально: `npx playwright install chromium`, затем после сборки `npm run test:browser`. Тесты используют Chromium с программным WebGL 2 и воспроизводят отказы параметров контекста, сбой Three.js, потерю контекста и загрузки модулей. Это не проверка физического Android или Яндекс Браузера.

## Прототип 0.2

Суставные позы, вертикальный контакт молота с землёй и взмах меча правой рукой синхронизированы с прежними событиями боя. Отдача корпуса и hitstop не оглушают робота и не меняют боевые параметры. Проверьте лично перенос веса, читаемость замаха, ощущение контакта и сочетание удара с движением.

## Проверка тяжёлой атаки ПР-7

Добавьте `?hammerDebug=1` к адресу игры: отдельный просмотр с игрового ракурса
воспроизводит только риг робота на 25% скорости. Бой при этом не запускается.
Панель позволяет остановить воспроизведение, перемотать удар, выбрать 0°/90°/180°/270°,
выключить суставы и траекторию головки. «Вернуться в игру» полностью отключает режим.
Замах занимает прежние 1.16 с, контакт/окно удара — 0.25 с, восстановление — 1.8 с.

Во время подготовки робот делает короткий шаг и переносит вес, затем фиксирует стопы
до разгрузки молота. Головка поднимается снаружи плеча, проходит над головой и ускоряется
по дуге к прежней точке `slam`. Кисть следует рукояти через двухзвенный IK; для прохода
над головой плоскость локтя дополнительно стабилизирует вращение плеча.

### Cloudflare Workers Preview

`wrangler.jsonc` задаёт статические ресурсы `dist` и отдельный Preview без привязок
к production-ресурсам. Версия Wrangler зафиксирована в devDependencies.
В Cloudflare **Settings → Build** для веток предварительного просмотра:

- Build command: `npm run build:cloudflare`
- Preview / non-production deploy command: `npm run preview:cloudflare`

В `wrangler preview` параметр `--assets` не поддерживается: каталог задаётся в
конфигурации. Сборка Cloudflare использует `/` для ресурсов, GitHub Pages сохраняет
свой прежний путь. Production deploy command и ветку `main` для проверки PR менять
не требуется. После сохранения настроек повторите сборку ветки PR. Проверяйте
выданный Cloudflare URL, загрузку WebGL и номер сборки перед тестированием на телефоне.
